# Archiver（Legacy Recipe 補助スクリプト）

Legacy Recipe で蓄積した `output.csv` / `tags.txt` を棚卸する（矛盾を見つけやすく・検索しやすくする）ためのデスクトップアプリです。
Legacy Recipe 本体とは別スクリプトとして独立しています。

## できること

指定したフォルダ（サブフォルダも含めて再帰的に探索）にある `tags.txt` と `output.csv` を対象に、以下の4つの処理を行います。

1. **①タグの件数カウント**：見つかった全タグについて、`output.csv` 内で何回使われているかを集計し、`files/all_tags_count.csv` に出力
2. **②指定タグの情報を抽出**：選択したタグ（複数選択可）が1つでも付いているレコードを抽出し、`files/tags_output_タグ名.csv`（例：`tags_output_DR1_DR2.csv`）に「項目・入力すべき内容・情報1・情報2…」という横長形式で出力。ファイルの最終行には、抽出したレコードの中で最も新しい「記録日」を**最終記録日**として記録する
3. **③索引ファイルの生成**：タグごとに、そのタグが登場する `output.csv` のファイル名（探索フォルダからの相対パス）一覧を `files/index.csv` に出力
4. **④継続的な統合**：②で作った `tags_output_タグ名.csv` を棚卸（手で編集・整理）した後、そのファイルを指定して実行すると、ファイル名から復元したタグ・ファイル内の「最終記録日」を基準に、それ以降（同日を含む）に増えた該当レコードを `output.csv` から探し、既存の内容の末尾に追加する。既存レコードと内容が完全一致するものは重複追加しない。既存ファイルを指定した時点で、ファイル名から復元したタグをUI上に表示する

## 画面の流れ

1. 起動 → メイン画面表示
2. 実行したい処理（①〜④のいずれか）をラジオボタンで選択
3. 対象フォルダを指定（デフォルトは `files/` 直下。「参照...」ボタンでダイアログ選択も可能）
4. ②を選んだ場合のみ、「タグ候補を読み込む」でそのフォルダ配下のタグ一覧をチェックボックスとして表示し、使いたいタグにチェック（複数選択可）
5. ④を選んだ場合のみ、更新対象の既存 `tags_output_タグ名.csv` を指定（「参照...」ボタンでダイアログ選択も可能）
6. 「実行」ボタンを押すと処理が走り、対象のCSVファイルが `files/` に生成・更新される
7. 完了ダイアログが表示される

## 必要なもの

- Python 3.10 以上を推奨
- 標準ライブラリの `tkinter`（Windows/macOS向けPythonには同梱。Linuxの場合はOS側で別途インストールが必要な場合あり）
- 追加パッケージ：**customtkinter**

```bash
pip install customtkinter
```

## フォルダ構成

```
archiver_app/
  __main__.py              起動エントリーポイント
  run_test.py               `python -m run_test` で①②③のテストを実行するためのラッパー
  version.py                バージョン定義（__version__）
  files/                    フォルダ指定欄のデフォルト対象／生成物の出力先
    all_tags_count.csv      ①の出力（実行すると生成される）
    tags_output_タグ名.csv   ②の出力・④の更新対象（実行すると生成される。例：tags_output_DR1.csv）
    index.csv               ③の出力（実行すると生成される）
  model/
    field_meta.py           output.csv の列（項目名・入力すべき内容）の定義
    scanner.py               tags.txt / output.csv の再帰探索・読み込み
    aggregator.py             ①②③④の集計ロジック・ファイル名生成・CSV読み書き
  controller/
    app_controller.py       View非依存のアプリケーションロジック
  view/
    style.py                 フォント設定（Legacy Recipeと同じサイズ体系・メイリオ）
    main_window.py           唯一の画面（処理選択・フォルダ指定・タグ選択・実行）
  tests/
    dummy_data/
      tags.txt              テスト用ダミータグ（10件）
      output.csv             テスト用ダミーレコード（40件）
      after_output.csv       output.csvに10件追加したもの（④の動作確認用）
    results/                 run_dummy_tests.py の実行結果（実行のたびに再生成）
    test_controller.py       Model / Controller の自動テスト（一時フォルダで実行）
    run_dummy_tests.py       dummy_data を使って①②③を実際に実行するスクリプト
```

本アプリも Legacy Recipe と同様にMVCモデルで実装されており、View（customtkinter）は Model / Controller に依存しますが、Controller は View に一切依存しません。そのためGUIを起動せずにロジック部分だけをテストできます。

## 起動方法（プロトタイプ）

```bash
cd [archiver]
python __main__.py
```

バージョンを確認したいだけの場合は以下を実行してください（GUIは起動しません）。

```bash
python __main__.py -v
python __main__.py --version
```

## テスト方法

GUIを介さず、Model / Controller のロジックのみをコマンドプロンプトから直接テストできます。
`tests/dummy_data/`（output.csv 40件・tags.txt 10件）を一時フォルダにコピーしてから実行するため、`files/` 配下は汚れません。

```bash
python -m unittest discover -s tests -v
```

または pytest がインストールされていれば

```bash
python -m pytest tests -v
```

テストは以下を含みます。

- フォルダ指定のバリデーション、タグ候補の再帰読み込み
- ①タグ件数カウントが正しい件数・タグ数で `all_tags_count.csv` を生成すること
- ②単一タグ／複数タグ（OR条件）／該当なしタグでの抽出結果の違い、ファイル名がタグ名から正しく生成されること、末尾に「最終記録日」が記録されること
- ③索引ファイルが正しいタグ・ファイル一覧を出力すること
- ④「最終記録日」より前のレコードは追加されず、それ以降のレコードのみが追加されること／同じ内容のレコードは重複追加されないこと
- 複数フォルダ・複数ファイルにまたがるタグ・レコードを正しく再帰的にマージできること

### 実際の生成物を目視確認したい場合

`tests/dummy_data`（output.csv 40件・tags.txt 10件）を対象に①②③を実際に実行し、
結果ファイルを `tests/results` に保存するスクリプトも用意しています。
さらに④の動作確認として、`tests/dummy_data/after_output.csv`（output.csvに10件追加したもの）を使い、
②の結果ファイルに対して継続的な統合を試します（既存ファイルは上書きせず、`tags_output_タグ名_after.csv` として別名で保存されます）。

`archiver_app` フォルダ直下から、`cd tests` をせずに実行できます。

```bash
python -m run_test
```

- **②④で使うタグ（デフォルト）**：指定しない場合は `DR1` のみを使います
- **②④で使うタグ（指定する場合）**：`-tag` オプションにカンマ区切りで渡します（前後の空白は自動的に除去されます）
  ```bash
  python -m run_test -tag "a, b, c"
  ```
- **テスト結果の保存先**：`tests/results/` フォルダ（実行のたびにクリアしてから再生成されます）
  - `all_tags_count.csv` … ①の結果
  - `tags_output_DR1.csv`（または指定したタグ名のファイル） … ②の結果
  - `index.csv` … ③の結果
  - `tags_output_DR1_after.csv`（または指定したタグ名+`_after`のファイル） … ④の結果

`after_output.csv` は、`output.csv`（40件）に加えて全く異なる10件を追加したデータです。
そのうち4件にタグ `DR1` を付けており、1件（`after-1`）は意図的に②実行時の最終記録日（`2026/10/22`）より
古い日付（`2026/01/05`）にしています。④実行後、この `after-1` だけが除外され、
残り3件（`after-2`〜`after-4`）のみが追加されることを確認できます。

（`tests` フォルダに移動して `python run_dummy_tests.py` を直接実行する方法も、これまで通り使えます。`python -m run_test` はそのラッパーです。）

## ④継続的な統合についての注意点

- タグの復元はファイル名（`tags_output_DR1_DR2.csv` → `["DR1", "DR2"]`）から行っています。タグ名自体にアンダースコアが含まれる場合は正しく復元できません
- 「最終記録日以降（同日を含む）」で対象を絞り込むため、最終記録日と同じ日付の別レコードが後から追加された場合、正しく拾えます。一方で、既存レコードの内容を棚卸で編集した場合、その編集後の内容と `output.csv` 側の生データは完全一致しなくなるため、重複排除の対象にならず、編集前の内容が再度追加されることがあります。これは「編集した内容と元データが食い違っている」ことの検知にもつながるため、あえて自動では消さず、棚卸時に人が見比べて判断する設計にしています
